这三道题表面上分别在问传输时间、交换方式比较和最优分组长度，实际上考的是同一条知识链：

> 数据从一个大文件变成分组，再变成链路上的 bit；分组经过多条链路时，如何计算时延，以及如何在首部开销和流水线效率之间取得平衡。

这篇笔记不只记录答案，也把做题时暴露出来的概念缺口整理出来，方便之后复习时从模型出发，而不是只背公式。

## 一、三道题分别在考什么

| 题目 | 主要模型 | 核心知识 |
| --- | --- | --- |
| 2010 年题 34 | 固定大小分组经过多条链路 | 分组数、发送时延、存储-转发、流水线 |
| 1-10 | 电路交换与分组交换比较 | 连接建立时间、公共传输时间、分组转发等待 |
| 1-11 | 选择合适的分组数据长度 | 首部开销、分组数量、时延优化 |

可以把三题串成：

~~~text
交换方式 → 分组 → 发送时延 → 存储-转发 → 流水线 → 分组长度优化
~~~

## 二、先把基础模型固定下来

### 1. 报文、分组、帧和 bit

一个文件不会直接以“整个文件”的形式一次性通过网络。抽象地看，它会经历：

~~~text
文件 / 报文
    ↓
分组
    ↓
帧
    ↓
bit
~~~

- **报文**：应用层要发送的完整数据。
- **分组**：网络层把报文切成的小块，是分组交换中的基本单位。
- **帧**：数据链路层在一条链路上的传输单位。
- **bit**：物理链路上真正依次传输的 0 和 1。

本专题最重要的一句话是：

> 存储-转发设备等待的是一个完整分组，而不是整个文件，也不是刚收到的第一个 bit。

### 2. 三个常用时间量

**发送时延**：把长度为 L bit 的数据推入链路需要的时间。

~~~text
d_trans = L / R
~~~

其中 R 是链路速率，单位必须是 bit/s。

**传播时延**：一个 bit 在链路中从一端跑到另一端需要的时间。

~~~text
d_prop = D / V
~~~

其中 D 是链路长度，V 是信号传播速度。

两者不要混在一起：数据越大主要影响发送时延，距离越长主要影响传播时延。教材题没有给出处理时延、排队时延或传播时延时，就不要凭直觉额外添加一项“接收时延”。接收端陆续收到一个分组的过程，已经包含在发送端把这些 bit 依次推出去的时间关系里。

### 3. 做题前先统一单位

~~~text
1 B = 8 bit
1 Mbps = 10^6 bit/s
1 s = 1000 ms
~~~

最容易错的是大小写：b 通常表示 bit，B 表示 Byte；Mb 是兆比特，MB 是兆字节，二者相差 8 倍。看到 1000B 和 100Mbps 时，应该条件反射地写成：

~~~text
1000B = 8000bit
100Mbps = 100 × 10^6bit/s
~~~

## 三、2010 年题 34：存储-转发与流水线

### 已知条件

- 文件大小：980000B
- 一个完整分组大小：1000B
- 每个分组首部：20B
- 链路速率：100Mbps
- 最短路径包含 3 条链路
- 不考虑传播时延

### 第一步：求一个分组携带的有效数据

一个分组总长是 1000B，其中 20B 是首部，因此真正携带文件内容的是：

~~~text
1000 - 20 = 980B
~~~

### 第二步：求分组数量

~~~text
N = 980000 / 980 = 1000
~~~

所以文件会被切成 1000 个分组。

### 第三步：求一个分组在一条链路上的发送时延

完整分组大小必须包括首部：

~~~text
1000B = 8000bit
~~~

因此：

~~~text
d_trans = 8000 / (100 × 10^6) s
         = 0.00008s
         = 0.08ms
~~~

### 第四步：利用存储-转发流水线

第一个分组要依次经过 3 条链路，所以需要 3 × 0.08ms。第一个分组之后，后续分组可以像流水线一样继续发送，每隔 0.08ms 到达一个。

因此总时间是：

~~~text
T = (N + K - 1) × d_trans
  = (1000 + 3 - 1) × 0.08ms
  = 80.16ms
~~~

答案：

~~~text
80.16ms
~~~

这里不能算成 N × K × d_trans，因为那相当于假设每个分组都要独占地走完所有链路，漏掉了分组之间的流水线并行。

## 四、1-10：电路交换和分组交换比较

设：

- 报文长度为 x bit；
- 路径包含 k 条链路；
- 每条链路传播时延为 d；
- 链路速率为 b bit/s；
- 电路交换建立连接需要 s 秒；
- 分组的数据部分长度为 p bit；
- 先按题目常见模型假设 x 能被 p 整除，且忽略排队时延。

### 电路交换

电路交换先花时间建立连接，再连续发送整个报文：

~~~text
T_c = s + x / b + kd
~~~

其中 x / b 是真正发送完整报文的时间，kd 是经过 k 条链路的传播时延。

### 分组交换

分组数量为：

~~~text
N = x / p
~~~

每个分组的发送时延为 p / b。采用存储-转发并形成流水线后：

~~~text
T_p = (x / p + k - 1) × p / b + kd
~~~

展开：

~~~text
T_p = x / b + (k - 1)p / b + kd
~~~

### 比较两种方式

要求分组交换更快：

~~~text
T_p < T_c
~~~

代入后，x / b 和 kd 是两种方式都必须承担的公共部分，可以直接抵消：

~~~text
(k - 1)p / b < s
~~~

因此：

~~~text
p < sb / (k - 1)
~~~

这道题真正考的不是机械移项，而是看出：

- 电路交换额外付出的是连接建立时间 s；
- 分组交换额外付出的是流水线填充时间 (k - 1)p / b；
- 最终发送这些数据和经过这些距离的公共时间，并不能因为交换方式不同而消失。

## 五、1-11：为什么存在最佳分组长度

这题比前两题更进一步：分组不能只考虑“数量越少越好”，因为分组变大后，流水线填充等待也会变长。

设：

- 原始报文长度为 x bit；
- 每个分组的数据部分为 p bit；
- 每个分组固定首部为 h bit；
- 路径包含 k 条链路；
- 链路速率为 b bit/s。

一个完整分组的长度是：

~~~text
p + h
~~~

分组数量为：

~~~text
N = x / p
~~~

所以总时延为：

~~~text
T = (x / p + k - 1) × (p + h) / b + kd
~~~

展开后：

~~~text
T = [x + xh / p + (k - 1)p + (k - 1)h] / b + kd
~~~

其中真正随 p 改变的部分只有：

~~~text
xh / p + (k - 1)p
~~~

### 分组太小的问题

当 p 很小时，分组数量会变多，首部也会重复很多次：

~~~text
xh / p 变大
~~~

有效数据比例下降，首部开销占比上升。

### 分组太大的问题

当 p 很大时，每个分组的发送时间变长，经过多条链路时流水线的填充等待也会增加：

~~~text
(k - 1)p 变大
~~~

### 求平衡点

对 xh / p + (k - 1)p 求导并令导数为零：

~~~text
-xh / p^2 + (k - 1) = 0
~~~

得到最优的数据部分长度：

~~~text
p* = √[xh / (k - 1)]
~~~

也可以把它理解成两种代价相等的平衡点：

~~~text
xh / p = (k - 1)p
~~~

这是假设可以连续取值、且忽略 MTU 和最后一个不足分组等现实限制时的理论答案。实际设计还要受最大帧长、整数分组数和协议限制约束。

## 六、这次暴露出的知识点疏漏

### 1. 交换单位没有完全稳定

容易把“交换机收到什么才可以继续转发”混成首部、bit、整个文件。应该重新固定：

| 交换方式 | 主要等待或占用的单位 |
| --- | --- |
| 电路交换 | 先建立一条端到端的线路 |
| 报文交换 | 收到完整报文后再转发 |
| 分组交换 | 收到完整分组后再转发 |

### 2. 数据层次还不够清晰

原先容易形成“文件直接变成 bit”的模型，缺少中间的分组和帧。这会连锁影响分组数量、存储-转发和流水线的理解。

以后看到大文件时，先画：

~~~text
文件 → 分组 → 帧 → bit → 链路
~~~

### 3. B、bit 和速率单位容易混淆

最优先需要练到条件反射的三组转换是：

~~~text
B → bit：乘 8
Mbps → bit/s：乘 10^6
s → ms：乘 1000
~~~

尤其注意 Mb 不等于 MB，Mbps 也不是 MB/s。

### 4. 发送时延和传播时延容易混淆

可以用两个问题区分：

- L / R：把这串数据完整推出链路入口，需要多久？
- D / V：信号从链路一端跑到另一端，需要多久？

“接收端持续了 L / R 时间才收完”不是额外的第三段接收时延，而是发送端依次推出 bit 后在传播端呈现出的同一段时间关系。

### 5. 流水线意识不足

错误模型是：

~~~text
分组 1 到终点 → 分组 2 开始
~~~

正确模型是：

~~~text
链路 1：分组1 分组2 分组3
链路 2：      分组1 分组2
链路 3：            分组1
~~~

正因为不同分组可以同时占用不同链路，才会出现 N + K - 1，而不是 N × K。

### 6. 公式会写，但从题意建模还不够自动

目前已经能够理解发送时延、传播时延、首部开销和最优分组长度的推导，但下一步要练的是：先判断交换模型、单位和链路数，再决定公式，而不是看到数字就直接套式子。

## 七、目前的知识状态与复习顺序

| 知识点 | 当前状态 | 下一步 |
| --- | --- | --- |
| 发送时延 L/R | 已基本理解 | 继续练单位统一 |
| 传播时延 D/V | 已基本理解 | 和发送时延放在同一时间轴比较 |
| B/bit 转换 | 需要强化 | 单独做单位题 |
| 分组概念 | 刚建立 | 反复画“文件→分组→帧→bit” |
| 存储-转发 | 基本理解 | 练不同链路数 |
| 流水线 | 理解中 | 重点区分 N+K-1 与 N×K |
| 三种交换方式 | 需要重新整理 | 用“交换单位”做对照 |
| 首部开销 | 已理解 | 和分组数量一起分析 |
| 最优分组长度 | 能理解推导 | 练从总时延式中找变量项 |

建议按下面的顺序继续：

1. 单位换算：B、bit、Mbps、s、ms。
2. 单链路时延：L/R + D/V。
3. 多跳存储-转发：(N + K - 1)L/R。
4. 电路交换与分组交换比较。
5. 首部开销与最优分组长度。

## 八、做题时的固定检查清单

1. 题目中的数据量到底是 B 还是 bit？
2. 速率是否已经统一成 bit/s？
3. 分组总长度是否包含首部？
4. 分组的数据部分和完整分组长度有没有区分？
5. 路径上是几条链路，而不是几个交换机？
6. 题目是否采用存储-转发，是否允许流水线？
7. 传播时延、排队时延、处理时延是否真的给出？没有给出就不要擅自添加。
8. 最后把结果从秒换成题目要求的毫秒，并检查数量级。

## 结语：先建立画面，再使用公式

这三道题暴露的主要问题不是“不会计算”，而是还没有完全建立这样一张时间图：

~~~text
文件
  ↓ 切分
分组
  ↓ 封装
帧
  ↓ 串行发送
bit
  ↓ 经过多条链路
发送时延 + 传播时延 + 存储-转发流水线
~~~

当这张图稳定下来，公式就不再是孤立的符号：L/R 表示把数据推出去，D/V 表示信号跑过去，N+K-1 表示分组在链路之间形成流水线，√[xh/(k-1)] 则表示首部浪费和流水线等待之间的平衡。
