# 关于我

你好，我是 mio。

这里是我的个人博客，也可以把它当成我在网上留给自己的一间小屋。侧栏上写着一句“四季正与你擦肩而过”，我挺喜欢它：时间不会停下来等我整理好一切，但我仍然可以把一路上真正想过、做过、喜欢过的东西留下来。以后回头再看时，我希望还能认出当时的自己，而不是只看到一串已经过时的标签。

我目前还在学习，也一直在做东西。我的注意力大多在计算机上：从数据结构、计算机网络、操作系统，到 Java、Spring、Web、Linux、Docker、软件测试和 AI Agent。我会写代码、搭博客、做小工具、折腾自动化，也会为了一个看起来并不大的问题查很久，或者把一个“勉强能用”的流程重新做一遍，只因为它还没有顺手到我满意。

我不是一开始就知道自己要走哪条路的人。很多时候，我是在课程、练习、项目和生活之间慢慢确认方向：先遇到问题，和 ChatGPT 讨论，把概念弄明白，再动手验证，最后把真正留下来的理解整理下来。学习对我来说不是把看过的内容收集起来，而是把“我大概知道”慢慢变成“我能解释、能使用，也能在下一次遇到类似问题时重新做出来”。

## 我在学什么，也在做什么

现在的我仍然在补计算机基础、数学和英语。数据结构、计算机组成、操作系统、计算机网络这些内容并不会因为学过一遍就彻底结束；Java、Spring、Web、Linux、Git、Docker、测试和 AI 相关的东西，也总会在真正动手时露出新的细节。我的学习进度并不总是整齐，有时会在一个主题上停留很久，有时又会因为新的问题临时拐到另一条路上，但我确实一直在继续。

我也在搭建一套属于自己的写作和知识整理方式。博客、Markdown、GitHub、Obsidian 和各种自动化工具，对我来说不是孤立的软件，而是让我可以把零散的学习和实践慢慢留下来的工具。它们偶尔也会把我折腾得很烦，不过当一张图片能顺利进入文章、一条笔记能在以后被找回来、一个页面真的按照预期运行时，我还是会觉得这些细节值得花时间。

## 电脑之外

除了代码，我喜欢阅读。技术书和学习资料当然会读，但我也想给书、文章以及那些暂时不能立刻变成“有用知识”的内容留一点位置。读到让自己停下来想一会儿的句子，看到一个值得记住的观点，我通常会想把它写下来；不一定马上形成一篇文章，先留下一个可以以后继续回来的入口也很好。

我也喜欢看番。追番对我来说不只是把一季的列表打完，有时候是因为喜欢某个角色，有时候是被一段关系、一个场景或一种情绪留住。这个网站里的 Anime 页面，记录的就是我看过、正在看、想看或者暂时放下的作品。它和技术文章没有太直接的关系，但它同样属于我真实生活的一部分。

我喜欢听歌，写东西、整理资料或者调一个页面的时候，旁边有一点声音会让过程变得更舒服。除此之外，我还喜欢做一些小而具体的事：整理文件和工作流，尝试新的工具，把重复的步骤自动化，或者把一个已经能用的页面调整到更接近自己想要的样子。它们未必都能被称为作品，却是我平时最容易投入进去的事情。

## 为什么还在写博客

因为很多东西如果不写下来，很快就会只剩下“我好像见过”。写作会迫使我重新确认：这个概念到底是什么，我是否真的理解，代码有没有实际跑过，结论是不是只是凭印象得来的。写博客也是一种回看自己的方式——看以前哪里没想明白，后来是怎么补上的，又有哪些答案在新的实践之后需要改写。

我不想把这里做成一份包装得很完整的简历，也不想假装自己已经准备好、什么都懂了。比起证明自己会多少技术，我更愿意留下一个问题是怎样被拆开的，一次失败是怎样被定位的，一个还在学习中的人怎样把事情一点点做完。对我来说，博客的价值不只是“发表”，而是让理解有地方安放，让时间真正留下痕迹。

## 这里会有什么

这里有相对完整的 Posts：技术文章、项目记录、教程、阅读文章和阶段复盘；也有会继续生长的 Notes：某个知识点、一道题、一段课堂内容，或者一个还没有完全想明白的问题。Posts 更像暂时整理好的结果，Notes 则允许保留过程和空白。一个 Note 经过多次补充、验证，也许会慢慢长成一篇正式文章；也有一些内容会一直保持短小，只在需要的时候帮我找回思路。

除了技术，这里也会留下阅读、番剧、音乐和生活里的小事。它们不一定都能组成一个宏大的主题，但正是这些不那么“有用”的部分，让这个地方更像一个人的博客，而不是一套冷冰冰的知识分类。

我把重要的东西尽量写成 Markdown，因为我希望知识是可以带走、可以迁移，也可以长期维护的。它不应该只停留在某个应用里，也不应该因为换了设备或工具就失去意义。这里的内容会有阶段性，会返工，会被新的理解改写；只要未来的我还能读懂，偶尔也能帮到另一个遇到相似问题的人，就已经值得。

## 如何添加友链

友链页面的数据放在项目里的 `shirones/config/data/friends.ts`。想添加一个站点时，在 `friendsData` 数组里追加一项，填写站点名称、头像、简介、网址和标签即可：

```ts
{
    id: 6,
    title: "站点名称",
    imgurl: "https://example.com/avatar.jpg",
    desc: "一句简短的站点介绍",
    siteurl: "https://example.com",
    tags: ["Blog"],
},
```

其中 `id` 不要和已有条目重复，`imgurl` 是头像地址，`siteurl` 是站点首页地址，`tags` 用来在友链页面筛选。保存后重新构建并发布，新的站点就会出现在 `/friends/` 页面；如果希望别人也添加你的站点，可以把自己的名称、头像、简介和首页地址按同样的格式发给我。

## 我在意的事情

我喜欢把复杂的问题拆开，把边界说清楚，把实际过程跑一遍。我不太满足于“页面上看起来能用”或“理论上应该可以”，更希望它真的运行过、验证过；如果没有做到，也应该把没有做到的部分说清楚。我也在意公开和私人的边界：这里分享的是适合公开的学习、实践与生活记录，不是把所有东西都无差别地摊开。

我没有把自己写成一个已经完成的人。现在的我仍然会迷茫，会返工，会在一个小问题上花掉比预想更多的时间，也会在某些日子里只是读一点东西、看一集番、听几首歌。然后继续学习，继续做东西，继续把值得留下的部分写下来。

如果你是因为某篇文章来到这里，欢迎从 Posts、Notes 或 Anime 开始往下看；如果你也在学习相似的东西，或者发现文章里有错误和不同的理解，也欢迎来交流。你可以通过导航栏中的 GitHub、X 或 Bilibili 找到我。
