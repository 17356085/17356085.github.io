横幅沿用主题的 `<picture>` 与桌面/手机断点；文章卡片的数据适配器提供
`srcset`，由浏览器按布局和屏幕密度选取。文章中的原图与 frontmatter 不变。
`OptimizedPostCard.astro` 基于 Shirones 0.1.4 的 organisms/PostCard 数据适配器，
样式和交互仍由主题的 atoms/blog/PostCard 提供；升级主题时应核对数据适配器。

图床生成命令：

```powershell
node scripts/media/optimize-site-images.mjs
node scripts/media/optimize-site-images.mjs --publish
```

默认只准备本地副本，第二条命令才上传到现有 R2 并写入封面映射。
文件名包含内容哈希，原始图床对象不会被覆盖；上传后逐个确认公开地址可访问。
新封面需加入生成器的来源清单并重新生成映射。

## 字体

保持 Yozai 字形、`font-display: swap` 和不预加载。字体按互斥 Unicode 范围分包，
全字形覆盖和构建缓存详见 [font-subsets.md](./font-subsets.md)。构建资源总量与
浏览器实际下载量不同：完整分包约 8.5 MB，页面只请求出现字符所在的包。
因此收益应以网络面板中的实际字体请求总量衡量，不把完整分包压缩率当作首屏收益。

Astro 配置在读取字体配置之前生成分包；生成文件不进入 Git。
当前 Astro 7 的 local provider 需要 `unicodeRange: string[]`，而 Shirones 0.1.4
声明为 `string`，配置中保留了一处带说明的兼容转换。

## 看板娘加载

页面解析完成并绘制两帧后，空闲调度再动态导入 Live2D 运行模块。
不再等待整个页面的图片加载完成；休息和隐藏状态会阻止计划中的初始化。
已经开始的初始化保留原来的暂停、恢复和错误降级处理。

备用精灵背景仅在 `data-renderer="sprite"` 时赋值，正常 Live2D 模式不下载
261,138 B 的备用 idle 图片。备用素材仍保留，用于运行核心或 WebGL 初始化失败时降级。

纹理转换已核对全部可见像素与 alpha 一致，没有改变模型 UV、尺寸或动作参数。

## 测量边界

优化前的线上单次冷加载样本：FCP 4.476 s，横幅 LCP 16.584 s，
DOMContentLoaded 27.491 s，load 29.727 s；该样本的 Live2D 纹理到 77.926 s 才下载完。
这是本机当时网络下的样本，不能代表所有访客。缓存命中刷新与首次访问分别测量。
线上复测应关闭浏览器缓存一次，记录导航、Paint、LCP、资源请求、模型就绪状态，
再恢复浏览器缓存设置。开发服务器的首次编译耗时不能当作线上加载速度。
